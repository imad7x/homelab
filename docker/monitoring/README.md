# monitoring

| Service | Port | What |
|---|---|---|
| Prometheus | 9090 | metrics with 40 GB size-based retention; scrape config in `prometheus/prometheus.yml`, recording rules in `prometheus/rules/` |
| Grafana | 3001 | dashboards and datasources provisioned from files |
| node-exporter | 9100, host network | host metrics; runs as root only to read the CPU's RAPL energy counters |
| cAdvisor | 8082 | per-container metrics (pinned to v0.49.1) |
| Scrutiny | 8083 | S.M.A.R.T. history web UI, collects every 6 hours |

| Homepage | 3000 | the start page (`homepage/`, its own Compose project) |

## Grafana

Dashboards in `grafana/provisioning/dashboards/`:

- **My Lab** - power and electricity cost, system, containers, storage, health.
- **Disk Health** - S.M.A.R.T. data for every disk.
- **Media Usage** - Jellyfin usage from Jellystat plus Seerr, Radarr and Sonarr data.
  Generated by `dashboards-src/media_usage.py`; re-running it overwrites UI edits.
- **Finance** - generated by the finance stack and kept private (it is in the bundle).
- **Pi-hole Weekly** - a weekly DNS digest: blocking, top domains, sites new this week,
  devices, encrypted-DNS bypass attempts and LAN reverse lookups sent upstream, with a Week
  dropdown instead of the time picker. Generated by `dashboards-src/pihole_weekly.py`
  (`--check` also runs every panel query against the digest).
- **Health & Training** - recovery (HRV and resting HR against your own baseline), sleep
  stages, steps and wear time, heart rate, training load and lifts, from the gym stack's
  `health.db` (mounted read-only from `/docker/gym/state/grafana`). Hours the watch was off
  are gaps, not zeros. Generated by `dashboards-src/gym_health.py` (`--check` runs every query).

Datasources: Prometheus; Postgres for Firefly and Jellystat (read-only roles); three
Infinity datasources for the Seerr, Radarr and Sonarr APIs; and SQLite
(`frser-sqlite-datasource`) for the Pi-hole digest and the gym health file (`grafana/*.yml`). Both plugins are
installed by `GF_PLUGINS_PREINSTALL_SYNC`. Their
passwords and API keys come from `grafana-*.env` as environment variables. Grafana joins
the `finance_default` and `jellyfin_default` networks to reach those databases, so start
those stacks first.

## Pi-hole digest

`pihole-digest/pihole_digest.py` (Python standard library only, run from cron daily at 05:10)
reads Pi-hole's long-term query database read-only through
`docker exec pihole pihole-FTL sqlite3 -readonly` and writes `pihole-digest/digest.db`: one
snapshot per Monday-Sunday week (Asia/Kolkata) plus one row per day. Grafana mounts the
folder read-only.
The script is published here; `digest.db` is data and is not backed up (a re-run rebuilds
whatever Pi-hole still holds).

- Every week still in Pi-hole's database is rebuilt on each run, so the first run backfills
  and re-runs are safe. Pi-hole keeps 91 days; a week it has started to prune is left as
  stored, so the digest keeps older history.
- "New sites" are registrable domains not seen in the four weeks before, so they need four
  complete weeks of Pi-hole history.
- The router's own health checks are counted in the totals but left out of the top lists.
- The database is rebuilt in a copy and swapped in with a rename, so Grafana never reads a
  half-written file. `digest.db` is data and is not in this repo; neither is the script.

## Power and cost model

`prometheus/rules/homelab-power.yml` estimates the server's power draw as
`homelab:power_watts{component,source}` and `homelab:power_watts:total`. CPU and RAM are
measured through RAPL, the SSD and HDDs are estimated from disk busy time, and the board
(4 W) and adapter losses (85 % efficiency) are fixed estimates. Energy in kWh is
`sum_over_time(...) * 15 / 3.6e6`; the electricity tariff is a dashboard variable. Idle
draw is about 10-12 W. Without a wall-plug meter it is uncalibrated - a smart plug would
fix that.

## Notes

- `prometheus/` is owned by `nobody`. Write rules through the container
  (`docker exec -i prometheus sh -c 'cat > /etc/prometheus/rules/x.yml'`) and reload with
  `docker kill -s HUP prometheus`.
- The two named volumes are external. Before the first `up`, run
  `docker volume create monitoring_prometheus_data` and
  `docker volume create monitoring_grafana_data`.
